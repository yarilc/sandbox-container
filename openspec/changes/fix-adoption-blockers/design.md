# Design

## Context

Every adopting wrapper carries a `tests/test_reference_copy.py` that `tools/propagate.py` generated or updated while `claude-container` held the reference role. Its text contains:
- the docstring line `Per-agent check that the shared components equal the Claude reference copy.`;
- a docstring mention of ``claude-container``;
- `SIBLING = ROOT.parent / 'claude-container'`;
- the skip message `no sibling claude-container checkout`.

The tool parses only `REFERENCE_TAG`, `REFERENCE_COMMIT` and the `MANIFEST` block. The shared `tests/test_guard.py` borrows the provider fixture from each wrapper's per-agent `tests/test_network_runtime.py`, whose returned environment uses the wrapper's own variable names.

## Goals / Non-Goals

**Goals:**
- `--guard` passes in every wrapper once it adopts the tag, without changing any wrapper's `test_network_runtime.py`.
- After an applied run, a wrapper's sibling check compares against `sandbox-container`.

**Non-Goals:**
- Claude's adoption itself, including its first manifest. That is a separate change in `claude-container`.
- Other cleanups, such as shortening long requirement texts.

## Decisions

1. **The egress image is found by suffix.** `test_guard` takes the single environment entry whose name ends in `_EGRESS_IMAGE`, and fails with a clear message if there is none or more than one.
   - Alternative considered: an `egress_image` attribute on every harness. Rejected, because it needs a coordinated edit in five per-agent files for no extra safety.
   - The fixture name stays out of the lookup, so the test also works with the reference's own harness, which uses the fixture names.
2. **The manifest is renamed from the `SIBLING` line.** On apply, the tool reads the sibling name with `SIBLING = ROOT.parent / '<name>'`. When `<name>` differs from the directory name of the reference checkout:
   - it replaces every occurrence of `<name>` in the manifest with that directory name;
   - it rewrites `the <Word> reference copy` in the docstring to `the <reference name> reference copy`.

   The dry run prints `manifest: names <reference>` when it would do so. A manifest without a `SIBLING` line is rejected with a precondition error, like the other format checks; all current wrappers have one.
   - Alternative considered: hard-coding `claude-container` to `sandbox-container`. Rejected, because deriving the name from the checkout keeps the tool correct if the reference moves again.
3. **Tagging.** `tests/test_guard.py` is shared, so the change needs `sandbox-ref-20`. The checklist for a changed `tests/test_guard.py` is `--guard` and `--network`, plus the unit discovery and the propagation tests for the tool.

## Risks / Trade-offs

- [Another `_EGRESS_IMAGE` variable appears in a harness environment] → The lookup fails loudly instead of picking one.
- [A wrapper's manifest contains the old name in unrelated text] → Only `tests/test_reference_copy.py` is rewritten, and its text is fully generated by this tool, so every occurrence refers to the reference.

## Migration Plan

Tag `sandbox-ref-20` after the checklist passes, then adopt it per wrapper:
- Claude first: write its first manifest at `sandbox-ref-18`, then run the tool from `sandbox-ref-18` to `sandbox-ref-20`.
- Codex, OpenCode, Pi and Antigravity: run the tool from `sandbox-ref-18` to `sandbox-ref-20`.

`sandbox-ref-19` stays as history and is not adopted by any wrapper.
